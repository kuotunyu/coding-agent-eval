# v0.1.1 closure design

## Objective

Close the final advertised CLI stub and polish software-distribution metadata without
changing the BugSeed v0.1 corpus, any retained outcome, or any empirical claim. The
result is a software patch release: software version 0.1.1 over benchmark version 0.1.0.

## Non-goals

- No paid provider request, new suite registration, task, fixture, mutation, rerun, or
  human ruling.
- No change to reference-suite or smoke-run bytes, metric availability, pricing evidence,
  adapter identities, or the existing `v0.1.0` tag and Release.
- No DOI, Zenodo draft, or Zenodo publication.
- No new branch, clone, worktree, dependency, website, screenshot, or unrelated refactor.

## Standalone sanitization contract

The public command is:

```text
cae sanitize RUN_ID --store-root .run-store --out PATH [--force]
```

`RUN_ID` identifies an existing owner-only raw run beneath `--store-root`. It must be one
ordinary path segment: empty names, `.` or `..`, absolute paths, separators, and traversal
are refused. Opening an existing run must not create a directory as a side effect. A
missing events file, an empty run, malformed JSONL, or a malformed raw-record envelope is
reported without echoing raw content.

`PATH` must resolve outside the private store. Existing output is refused unless
`--force` is present. A successful forced write still uses the sanitizer's atomic replace
behavior. Every privacy, schema, or leak rejection leaves no new partial output and
preserves any previous output byte for byte. The command writes one sanitized public trace
only; it does not invent `run.json`, findings, scores, review decisions, or completeness.

Argparse and invalid operator syntax exit 2. A missing, malformed, or privacy-rejected run
exits 1. Success exits 0 and reports only event count plus the operator-provided output
path; no raw payload or private value is printed.

## Internal boundaries

The raw-store module will expose one read-only existing-run path that validates `RUN_ID`
and parses the append-only JSONL without creating storage. It returns raw event objects or
raises a value-free `RawStoreError`. The CLI owns argument validation, overwrite policy,
and user-facing exit codes. The existing `sanitize_events` function remains the single
projection, allowlist, leak-scan, and atomic-write implementation.

This separation keeps raw persistence, public projection, and CLI policy independently
testable. `cae run` continues using the same sanitizer automatically and is not changed.

## Versioning and evidence identity

- Package metadata and `__version__` advance to 0.1.1.
- `BENCHMARK_VERSION` stays 0.1.0, as do task registry, fixture, schema, run, suite, and
  release-manifest benchmark identities.
- `cae --version` prints both identities: `cae 0.1.1 (benchmark 0.1.0)`.
- `CITATION.cff` and prepared `.zenodo.json` describe software version 0.1.1 while still
  stating that no DOI or Zenodo record exists.
- README and Release Readiness describe v0.1.1 as a tooling patch with no new empirical
  evidence.

## Distribution and GitHub surface

Add project URLs, keywords, and conservative Python/MIT/OS-independent/AI-development
classifiers to wheel metadata. Exclude `docs/superpowers/` from the sdist; those internal
design records remain in Git history and the working repository but are not end-user
package content. Wheel schema inclusion and all benchmark artifacts remain unchanged.

After the source commit and CI succeed, update GitHub About to an English recruiter-facing
description and retain the existing evidence-oriented topics while adding
`developer-tools` and `python`. No website or homepage is invented.

## Tests and verification

Tests are written before implementation and must demonstrate the existing stub failure.
Coverage includes successful projection, exact deterministic bytes, invalid/traversing run
IDs, missing and empty runs, malformed JSONL/envelopes, unknown fields, sensitive values,
private-store output refusal, existing-output refusal, `--force`, atomic failure, and no
raw value in diagnostics. Package tests assert the two version identities, metadata URLs,
and absence of `docs/superpowers/` from the sdist.

Before release, run Ruff, format check, strict mypy, full non-Docker pytest, fixture
validation/rebuild/witness cycles, tracked leak scan, offline and online publication audits,
wheel/sdist build and privacy inspection, clean-export installed-wheel verification, all
Docker gates, and GitHub CI on Windows, Linux, and Docker. Confirm one `main` worktree,
owner-only provenance, one GitHub Contributor, clean HEAD equal to `origin/main`, and exact
asset digests.

## Release gates

The owner has approved an annotated `v0.1.1` tag, GitHub Release, and GitHub About update
after all verification succeeds. The new tag must point to the verified source commit and
must not move or replace `v0.1.0`. Release notes must call this a software/tooling patch,
retain the failed-smoke and no-verified-metrics boundary, and state that no DOI or Zenodo
record is claimed. Zenodo remains prohibited.
