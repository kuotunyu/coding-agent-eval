# v0.1 release readiness and acceptance contract

## Decision

BugSeed v0.1 is a reproducible **methodology preview**, not an AI Developer Tools / LLM
Evaluation flagship and not a model-ranking benchmark. Preparing citation and Zenodo
metadata is appropriate; publishing a GitHub Release or Zenodo record is not.

The distinction is deliberate:

- **Mechanical acceptance** asks whether the repository's contracts and evidence pipeline
  work as declared.
- **Publication acceptance** asks whether the corpus, adjudication, and contributor
  provenance support a public benchmark claim.

Mechanical acceptance does not waive publication acceptance.

## Evidence interpretation

- The `perfect` and `high_noise` baselines are deterministic evaluator fixtures. Their
  success rates are chosen inputs, not empirical agent performance; their zero/undefined
  cost and latency must never be compared with a model.
- The four committed baseline results test evaluator arithmetic. They are generated by a
  deterministic script, use a synthetic ledger, and describe no model.
- The eight historical live attempts test harness behaviour under one provider/model and
  one fixture. Two ended in zero-usage provider errors; six billable runs record estimated
  costs totaling $0.399115 and run-level wall time. They lack current-contract per-call
  latency/replay provenance, are not a representative baseline, and support no success-rate
  claim.
- The termination taxonomy and timeout/budget paths are deterministic test coverage. The
  historical live sample observed only provider error, token-budget exhaustion, and normal
  completion, so it does not establish real-world frequencies for other failure classes.
- Sandbox containment is an observed implementation property, not a security certification.
  `host_process` remains a valid but explicitly weaker backend, and every result must name
  the backend used.
- First-party, newly authored mutations reduce historical-fix contamination risk but do not
  eliminate target leakage. Public exposure causes contamination resistance to decay.

## Zenodo disposition

**NO-GO for publication.** `CITATION.cff`, `.zenodo.json`, and
`release-manifest.json` are prepared so metadata can be reviewed and reproduced locally.

Reassess only after P1–P6 pass.
